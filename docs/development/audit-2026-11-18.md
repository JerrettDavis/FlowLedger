# Pre-onboarding audit (2026-11-18)

Read-only security and performance review ahead of onboarding more users. Items marked **Done** shipped on master;
the rest are open and ordered by priority.

## Done
- Merchant-only manual/CSV transactions no longer receive a random orphan `CategoryId`.
- Optional sign-up allowlist (`Auth:Oidc:AllowedEmails` / `AllowedEmailDomains`, verified email required).
- `/auth/login` returnUrl rejects control characters (open-redirect edge case).
- MX connect-token and named (paid) asset-valuation feeds restricted to the household tenant.
- 5 MB request cap on CSV and bill-sheet import.
- Query datasets built once per request (dashboard insights loaded all history three times).
- Scheduled sync logs throttle / already-running / provider rate-limit outcomes at Info/Warn, not Error.
- Post-sync alias/rule/enrichment passes skipped when a sync adds no transactions.
- Category-merge split repoint is tenant-scoped; Web forwarded-headers support (opt-in `ForwardedHeaders__Enabled`).
- `/auth/relogin` refuses cross-site requests (Sec-Fetch-Site); CSV import capped at 50,000 rows; dashboard activity cap raised 5k -> 15k (newest-first, so only oldest baseline drops).
- API logs a warning when Development runs with the public dev key.

## Open - security (highest first)
1. **Run the onboarded stack with `ASPNETCORE_ENVIRONMENT=Production` and a real `Api__Key`, or at minimum set `Tenancy:RequireTenantHeader=true` (shipped, opt-in, tested).** AppHost launches
   Development, where a missing `X-Tenant-Id` falls back to the household tenant. Needs an operator decision and a
   restart, so it was not changed unattended.
2. Replace the shared API key + caller-supplied `X-Tenant-Id` trust with a Web-signed (HMAC / short-lived JWT) tenant
   assertion verified by the API.
3. Per-tenant row/storage quotas; rate-limit `/api/users/resolve` per IP.
4. `/auth/relogin` is still a GET (now cross-site-guarded); make it POST + antiforgery eventually.
5. Restrict `AllowedHosts` (forwarded-headers support is now opt-in).
7. Snapshot import: cap total uncompressed size. Export includes `app_users` PII and is unencrypted on disk.
8. MX webhook: add replay protection (event id / timestamp window).
9. `SensitivePropertyMaskingEnricher` is not wired (Serilog unused) - remove or wire up.

## Open - performance
1. Post-sync pipeline (`CategorizingSyncService`) does up to four tracked 50k-row loads per tenant per sync; filter to
   new/uncategorised rows or share one load.
2. Other endpoints scan up to 50k rows per request (`SpendingInsights`, `InvestmentPerformance`,
   `RecurringSuggestionService`, `BillSheetService`, `DashboardActivity` which also silently truncates at 5000):
   push date windows into SQL and/or cache per tenant briefly.
3. Worker syncs tenants serially (`TenantFanOut`); bounded parallelism needs the TenantFanOut tests rewritten (they assert serial order) - fine at tens of tenants.
4. Partial index for pending rows (the `(TenantId, EffectiveDate DESC, CreatedAt DESC)` index shipped; applies on next restart).
5. Minor: per-account upsert lookups in sync, per-asset account lookups, static sync lock dictionary growth.
